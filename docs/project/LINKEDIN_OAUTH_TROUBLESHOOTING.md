# LinkedIn OAuth Configuration - Troubleshooting Guide

## ✅ Issue Fixed: "Provider is not enabled"

### Problem
When clicking "Continue with LinkedIn", the browser showed:
```
error: 400 {"error":"unsupported_provider","error_description":"Unsupported provider: provider is not enabled"}
```

### Root Cause
The code was using `OAuthProvider.linkedin` but Supabase requires `OAuthProvider.linkedinOidc` for LinkedIn OIDC authentication.

### Solution Applied
✅ Changed from `OAuthProvider.linkedin` to `OAuthProvider.linkedinOidc` in `auth_service.dart`

---

## 🔧 Supabase LinkedIn OAuth Configuration

### Step 1: Enable LinkedIn Provider in Supabase

1. Go to your Supabase Dashboard: https://app.supabase.com
2. Select your project
3. Navigate to **Authentication** → **Providers**
4. Find **LinkedIn (OIDC)** in the list
5. Click to expand it
6. Toggle **Enable Sign in with LinkedIn** to ON

### Step 2: Configure LinkedIn OAuth Settings

You need to provide:

**Client ID**: Your LinkedIn App Client ID
**Client Secret**: Your LinkedIn App Client Secret
**Redirect URL**: This is auto-generated by Supabase

Example redirect URL format:
```
https://[YOUR-PROJECT-REF].supabase.co/auth/v1/callback
```

### Step 3: Configure LinkedIn Developer App

1. Go to [LinkedIn Developers](https://www.linkedin.com/developers/apps)
2. Select your app (or create a new one)
3. Navigate to **Auth** tab
4. Add **Authorized redirect URLs**:
   ```
   https://[YOUR-PROJECT-REF].supabase.co/auth/v1/callback
   ```
5. Under **OAuth 2.0 scopes**, ensure you have:
   - `openid`
   - `profile`
   - `email`

### Step 4: Copy Credentials to Supabase

1. In LinkedIn Developer Portal, go to **Auth** tab
2. Copy **Client ID**
3. Copy **Client Secret**
4. Paste both into Supabase LinkedIn (OIDC) provider settings
5. Click **Save**

## 🔍 Common Issues & Solutions

### Issue 1: "Provider is not enabled"

**Symptoms**: 
- Browser shows 400 error
- Error message: "Unsupported provider: provider is not enabled"

**Solutions**:
1. ✅ Ensure using `OAuthProvider.linkedinOidc` (not `linkedin`)
2. ✅ Enable LinkedIn (OIDC) in Supabase Dashboard
3. ✅ Save configuration in Supabase
4. ✅ Wait 1-2 minutes for changes to propagate

---

### Issue 2: "Invalid redirect URI"

**Symptoms**:
- LinkedIn shows error after login
- Error: "redirect_uri does not match"

**Solutions**:
1. Copy exact redirect URL from Supabase Dashboard
2. Add it to LinkedIn App's Authorized redirect URLs
3. Ensure no trailing slashes
4. Format: `https://[PROJECT-REF].supabase.co/auth/v1/callback`

---

### Issue 3: "Invalid client credentials"

**Symptoms**:
- OAuth flow fails
- Error about client_id or client_secret

**Solutions**:
1. Verify Client ID is correct in Supabase
2. Verify Client Secret is correct in Supabase
3. Regenerate credentials in LinkedIn if needed
4. Update Supabase with new credentials

---

### Issue 4: App doesn't open after LinkedIn approval

**Symptoms**:
- LinkedIn approval succeeds
- Browser doesn't redirect to app
- App doesn't open

**Solutions**:
1. Verify deep link configured in AndroidManifest.xml
2. Test deep link manually:
   ```bash
   adb shell am start -W -a android.intent.action.VIEW \
     -d "com.antigravity.aiinterviewcoach://login-callback"
   ```
3. Ensure app is installed and running
4. Check if deep link scheme matches exactly

---

### Issue 5: "Scopes not granted"

**Symptoms**:
- OAuth succeeds but profile data missing
- Email or name not synced

**Solutions**:
1. Ensure scopes requested: `openid profile email`
2. Verify scopes approved in LinkedIn App settings
3. User must approve all requested scopes
4. Re-authenticate to grant missing scopes

## 🔐 Security Best Practices

1. **Never commit secrets**: Keep Client Secret in Supabase only
2. **Use environment variables**: For local testing
3. **Rotate credentials**: If compromised
4. **Monitor usage**: Check Supabase logs for suspicious activity
5. **Limit scopes**: Only request what you need
